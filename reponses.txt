EXERCICE 2.1 - Cartographier l'écosystème

Java SE            Jakarta EE
---------          -----------
ArrayList          @Entity
javac              Servlet
Thread             JAX-RS
Stream             JPA
HashMap            CDI

Java SE regroupe le langage, la JVM et les bibliothèques de base : on peut
s'en servir sans serveur. Jakarta EE est un ensemble de spécifications pour
les applications d'entreprise : il faut un serveur d'application (Tomcat,
WildFly...) pour les exécuter.


SECTION 3 - Namespace jakarta.*

Oracle a transféré la plateforme Java EE à la fondation Eclipse en 2017 mais
a gardé la marque "Java". La plateforme a donc été renommée Jakarta EE, et à
partir de la version 9 les packages javax.* sont devenus jakarta.*. Seul le
nom des packages change, la logique du code reste la même.

Attention : Tomcat 9 et moins utilisent javax.*. Il faut Tomcat 10 ou plus
pour jakarta.*. Comme le pom.xml utilise jakarta.jakartaee-api 10.0.0
(Jakarta EE 10 = Servlet 6.0), j'ai utilisé Tomcat 10.1.


MINI-EXERCICE 4.1 - Annotations

Voir Livre.java. Une annotation n'exécute rien toute seule : c'est une
métadonnée que le framework (ici JPA) lit pour savoir quoi faire. @Entity dit
que la classe correspond à une table, @Id désigne la clé primaire,
@GeneratedValue la fait générer par la base, @NotNull et @Column posent les
contraintes du champ titre (obligatoire, 100 caractères max).


MINI-EXERCICE 4.3 - Map

Voir RappelsJavaSE.java, partie 1. Une Map<String, Integer> associe trois
fruits à leur prix, puis je la parcours avec entrySet() pour afficher chaque
paire clé-valeur.


MINI-EXERCICE 4.4 - Lambda et Stream

Voir RappelsJavaSE.java, partie 2. À partir d'une List<Integer> de 1 à 10 :
filter() garde les pairs (2, 4, 6, 8, 10), map() les multiplie par 2
(4, 8, 12, 16, 20), reduce() additionne le tout. Résultat : 60.


SECTION 4.5 - Fichiers

Voir RappelsJavaSE.java, partie 3. Je lis le fichier config.properties avec
java.nio.file (Path et Files) plutôt qu'avec java.io : c'est l'API moderne,
elle permet de lire ou d'écrire un fichier en une ligne.


EXERCICE 6.1 - pom.xml

jakarta.jakartaee-api est en scope provided parce que Tomcat fournit déjà
l'API à l'exécution. Si on l'embarquait dans le .war, il y aurait deux
versions des mêmes classes et des conflits au démarrage.

Le pilote postgresql reste en scope compile (le défaut) parce que Tomcat ne
fournit aucun pilote de base de données : il doit être dans le .war.
